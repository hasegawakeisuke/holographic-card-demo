ホログラフィックCSSの仕組み

画像やWebGLを一切使わず、グラデーション・合成モード・3D変形の3つだけで トレカの箔を再現しています。JavaScript がやるのは数値を4つ書き込むことだけで、 見た目の計算はすべてCSS側にあります。このページのカードは実際に動きます。

全体像 — 4枚の板を重ねる

カードは4層の重ね合わせでできています。下から順に、商品画像、虹色の層が2枚、 ポインタ追従の光沢が1枚です。すべて同じ位置に position: absolute; inset: 0 で 置かれ、重なり順は z-index で固定しています。

① 立体感 — perspective と rotate

カードが傾いて見えるのは rotateX() / rotateY() の2行だけです。 重要なのは回転させる要素の親に perspective を置くことです。 これが無いと回転しても平行投影のまま潰れて見え、奥行きが出ません。 

.card {
  perspective: 1400px;   /* 視点の距離。小さいほど強い遠近感 */
  isolation: isolate;    /* 合成をカード内で完結させる（後述） */
}

.card__inner {
  transform-style: preserve-3d;
  transform: rotateX(var(--rx)) rotateY(var(--ry));
  transition: transform .6s cubic-bezier(.23, 1, .32, 1);
  will-change: transform;
}
プロパティ役割
perspective子要素に遠近法を与える。値は「画面から視点までの距離」で、小さいほど歪みが強い
transform-stylepreserve-3d で子要素も同じ3D空間に置く。既定の flat だと子が平面に潰れる
rotateX / rotateY横方向のポインタ移動を Y軸回転に、縦方向を X軸回転に割り当てる（符号は反転）
will-change変形をGPU側に持ち上げ、毎フレームの再描画を避ける
transitionポインタが離れたときだけ効かせる。追従中は外して遅延をなくす

追従中は .is-active を付けて transition を切っています。 付けたままだと指の動きにカードが遅れて付いてきて、粘ついた感触になります。

② 追従 — JavaScriptは変数を書くだけ

JavaScript の仕事は pointermove でカスタムプロパティを4つ更新することだけです。 要素のスタイルを直接いじらないので、演出を変えたいときはCSSだけ触れば済みます。 下のカードを動かすと、実際に書き込まれている値が見えます。

// 座標を 0〜1 に正規化して、そのまま変数へ流し込む
const cx = px - 0.5, cy = py - 0.5;

card.style.setProperty('--mx', `${px * 100}%`);
card.style.setProperty('--my', `${py * 100}%`);
card.style.setProperty('--ry', `${ cx * 32}deg`);
card.style.setProperty('--rx', `${-cy * 32}deg`);
変数使われ先
--mx / --my虹色層の background-position と、光沢の radial-gradient の中心
--rx / --rytransform の回転角
--o効果全体の不透明度。ホバーで 0 → 1
--rest静止時の下限値。0 にすると触るまでただの写真に見えてしまう

更新は requestAnimationFrame で1フレームに1回へ間引いています。 pointermove は毎秒120回以上発火することがあり、そのたびに書き込むと無駄になります。

③ 虹色 — グラデーション＋合成モード

虹色そのものは repeating-linear-gradient で作ったただの縞模様です。 これを mix-blend-mode で下の層と混ぜることで、光を反射しているように見せています。 background-size を 200% にして余白を作り、background-position を ポインタ位置に連動させることで縞が流れます。 

.card__shine {
  background-image: repeating-linear-gradient(-22deg,
      #ff7773 4%, #ffed5f 10%, #a8ff5f 16%,
      #83fff7 22%, #7894ff 28%, #d875ff 34%, #ff7773 40%);
  background-size: 200% 200%;
  background-position: calc(var(--mx) * 1.2) calc(var(--my) * 1.2);
  mix-blend-mode: multiply;
  filter: saturate(1.4) contrast(.9);
}

なぜ2層必要か

本家 pokemon-cards-css は color-dodge の1層で成立します。ポケカの絵柄は 色が濃く、暗部が多いからです。ところがハンズの商品写真は白背景で、 color-dodge は明るい部分をさらに明るくする性質があるため、白地では完全に飛んでしまい、 何も見えなくなります。そこで性質が逆の multiply を重ねています。

同じ縞模様・同じ写真で、合成モードだけを変えた比較です

合成モード性質この実装での役割
multiply掛け算。明るい部分ほど下の色に染まる白い背景に虹色を乗せる
color-dodge除算。下が明るいほど飛ぶ、暗部が発光する枠や被写体の影を光らせる
overlay下の明暗を保ったままコントラストを付けるポインタ位置の光沢

filter は合成の前処理です。color-dodge 側に brightness(.85) contrast(1.6) を掛けて、飛びすぎないよう素材を沈めてから混ぜています。

④ 光沢 — 中心が動く放射グラデーション

光沢は radial-gradient の中心座標に変数を直接埋め込むだけです。 中心が白、外周が黒のグラデーションを overlay で合成すると、 中心は明るく、周辺は締まって見え、球面で光を反射しているように感じられます。 

.card__glare {
  background-image: radial-gradient(farthest-corner circle at var(--mx) var(--my),
      rgba(255,255,255,.85)  8%,
      rgba(255,255,255,.5)  20%,
      rgba(0,0,0,.35)      100%);
  mix-blend-mode: overlay;
  opacity: calc(var(--o) * var(--glare-opacity));
}

farthest-corner は「最も遠い角までを半径とする」指定です。 中心が端に寄っても光が途中で途切れず、カード全面を覆い続けます。

⑤ 強さの制御 — calc と max だけで分岐する

レアリティやタイプによる差は、すべて変数の掛け算で表しています。 CSSに条件分岐はありませんが、calc() と max() を使えば 「静止時は最低これだけ光り、ホバー時はここまで強くなる」を1行で書けます。 

opacity: calc(max(var(--rest), var(--o)) * var(--shine-opacity) * .85);
/*          ↑ 静止時の下限   ↑ 追従値    ↑ レアリティで変わる係数 */

レアリティは --shine-opacity を、タイプは --frame-* と --face-* を書き換えます。同じ詳細度のセレクタを記述順で競わせることで、 「色はタイプが勝ち、その上を ex が上書きする」優先順位を作っています。 

.card[data-rarity='ultra'] { --shine-opacity: .78; }  /* 光り方だけ */
.card[data-type='fire']     { --frame-b: #c2461c; }   /* 後に書いた方が勝つ */
.card[data-ex='true']       { --frame-b: #a8781f; }   /* さらに上書き */

⑥ 合成の閉じ込め — isolation: isolate

mix-blend-mode は既定ではページ全体の背景まで巻き込んで混ざります。 カードの外の背景色が変わると箔の見え方まで変わってしまいますし、 背景に敷いたグラデーションと干渉して意図しない色になります。

.card に isolation: isolate を置くと、そこが合成の境界になり、 混ざる相手はカード内部の層だけに限定されます。 1行ですが、これが無いと成立しません。

overflow: hidden や filter、transform も 同じく合成コンテキストを作ります。意図せず効果が閉じ込められて「なぜか混ざらない」ときは、 たいてい祖先のどれかがこれらを持っています。

⑦ 静止時のゆらぎ

ホバーしないと何も起きない作りだと、初見やスクリーンショットでただの商品写真に見えます。 そこで触っていないときだけ、背景位置をゆっくり往復させています。 

.card:not(.is-active) .card__shine {
  animation: shine-drift 9s ease-in-out infinite alternate;
}
@keyframes shine-drift {
  from { background-position: 12% 18%; }
  to   { background-position: 88% 82%; }
}

:not(.is-active) で限定しているのは、追従中にアニメーションが background-position を奪い合うのを防ぐためです。 alternate により終端で巻き戻らず、折り返して自然に見えます。
